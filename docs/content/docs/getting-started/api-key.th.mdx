## ขั้นตอน [#steps]

1. ไปที่ [sphere.gistda.or.th](https://sphere.gistda.or.th/) แล้วสมัครบัญชี
2. สร้าง API key
3. เพิ่มโฮสต์ (โดเมน) ที่แอปของคุณทำงานอยู่
4. เปิดบริการที่แอปของคุณใช้ (ดูด้านล่าง)

## โฮสต์ที่อนุญาต [#allowed-hosts]

เนื่องจาก key จะถูกส่งไปกับทุกคำขอและมองเห็นได้ในเบราว์เซอร์ รายชื่อโฮสต์จึงเป็นตัวป้องกันการนำ key ไปใช้ ให้เพิ่มทุกโดเมนที่แอปของคุณทำงาน:

| โฮสต์ | ใช้สำหรับ |
| --- | --- |
| `localhost` | การพัฒนาในเครื่อง |
| `example.com` | เว็บไซต์จริง |

<Callout>
  หากแผนที่ใช้ได้ที่พอร์ตหนึ่งแต่ใช้ไม่ได้อีกพอร์ต (เช่น ใช้ได้ที่ `localhost:3000` แต่ใช้ไม่ได้ที่ `localhost:5173`) ให้ตรวจดูว่าโฮสต์ที่ลงทะเบียนไว้ระบุพอร์ตไว้หรือไม่
</Callout>

## บริการ [#services]

แต่ละบริการของ Sphere ต้องเปิดใช้งานสำหรับ key ของคุณก่อน หากยังไม่ได้เปิด Sphere มักไม่แจ้งข้อผิดพลาดที่ชัดเจน ทำให้ฟีเจอร์ดูเหมือนไม่ทำงานเฉย ๆ ตารางนี้แสดงบริการที่แต่ละฟีเจอร์ต้องใช้:

| ฟีเจอร์ | บริการ | อาการเมื่อไม่ได้เปิด |
| --- | --- | --- |
| แผนที่ หมุด รูปทรง ชั้นข้อมูล | Map | แผนที่ว่างเปล่า |
| การค้นหาและคำแนะนำของ [`useSearch`](/th/docs/hooks/use-search), [`<Tag>`](/th/docs/components/tag) | Search, POI | `search`/`suggest` คืนข้อผิดพลาด ชั้นข้อมูลแท็กว่างเปล่า |
| `useSearch().address`, ที่อยู่ในเมนูคลิกขวา | Address (reverse geocoding) | `address()` คืนค่า `null` |
| [`<ObjectOverlay>`](/th/docs/components/object-overlay) | POI details (`poi/get`) | ไม่มีอะไรแสดง และ `onError` ทำงานเมื่อหมดเวลา |
| [`useRoute`](/th/docs/hooks/use-route), [`<RouteGuide>`](/th/docs/components/route-guide) | Routing | ข้อผิดพลาด `"timeout"` หลัง 20 วินาที โหมด Fly ยังใช้ได้ |
| [บริการเว็บ](/th/docs/web-services) | บริการที่ตรงกัน | `SphereServiceError` ที่มี code เป็น `"key"` |
| [แผนที่ภาพนิ่ง](/th/docs/web-services/maps-and-tiles#static-map-images) | Static map | โหลดภาพไม่สำเร็จ |

## การใช้ key [#using-the-key]

ส่ง key ให้ `SphereProvider`

```tsx
import { SphereProvider } from "gistda-sphere-react";

<SphereProvider apiKey="YOUR_API_KEY">
  <App />
</SphereProvider>
```

เก็บ key ไว้ในตัวแปรสภาพแวดล้อม (environment variable) เพื่อไม่ให้ติดไปกับซอร์สโค้ดใน Git

```bash title="Next.js: .env.local"
NEXT_PUBLIC_SPHERE_API_KEY=your_api_key
```

```tsx
import { SphereProvider } from "gistda-sphere-react";

<SphereProvider apiKey={process.env.NEXT_PUBLIC_SPHERE_API_KEY!}>
```

```bash title="Vite: .env"
VITE_SPHERE_API_KEY=your_api_key
```

```tsx
import { SphereProvider } from "gistda-sphere-react";

<SphereProvider apiKey={import.meta.env.VITE_SPHERE_API_KEY}>
```

<Callout type="warn">
  ตัวแปรที่มี prefix สำหรับเบราว์เซอร์ (`NEXT_PUBLIC_`, `VITE_`) ยังคงถูกรวมไว้ใน JavaScript ของคุณ สิ่งที่ปกป้อง key คือการจำกัดโฮสต์ หากเรียก [`createSphereServices`](/th/docs/web-services#on-a-server) ฝั่งเซิร์ฟเวอร์ ให้ใช้ key แยกอีกตัวที่ไม่มี prefix สำหรับเบราว์เซอร์ เซิร์ฟเวอร์ไม่ได้ส่งโฮสต์ที่ Sphere ใช้ตรวจสอบ ดังนั้น key ที่จำกัดโฮสต์ต้องกำหนดตัวเลือก `referer` ด้วย
</Callout>

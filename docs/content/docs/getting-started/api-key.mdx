---
title: Getting an API key
description: Get a GISTDA Sphere API key, restrict it to your sites, and enable the services you use
---

## Steps

1. Go to [sphere.gistda.or.th](https://sphere.gistda.or.th/) and create an account.
2. Create an API key.
3. Add the hosts (domains) where your app runs.
4. Enable the services your app uses (see below).

## Allowed hosts

The key is sent with every request and is visible in the browser, so the host list is what protects it. Add every place your app runs:

| Host | Purpose |
| --- | --- |
| `localhost` | Local development |
| `example.com` | Production |

<Callout>
  If the map works on one local port but not another (for example `localhost:3000` but not `localhost:5173`), check whether the host entry includes a port.
</Callout>

## Services

Each Sphere service has to be enabled for your key. When one isn't, Sphere usually doesn't report a clear error, so features just seem not to work. This table shows what each feature needs:

| Feature | Service | Symptom when missing |
| --- | --- | --- |
| The map, markers, shapes, layers | Map | The map stays empty. |
| [`useSearch`](/docs/hooks/use-search) search and suggestions, [`<Tag>`](/docs/components/tag) | Search, POI | Errors from `search`/`suggest`, empty tag layers. |
| `useSearch().address`, right-click menu address | Address (reverse geocoding) | `address()` resolves `null`. |
| [`<ObjectOverlay>`](/docs/components/object-overlay) | POI details (`poi/get`) | Nothing is drawn, and `onError` fires after the timeout. |
| [`useRoute`](/docs/hooks/use-route), [`<RouteGuide>`](/docs/components/route-guide) | Routing | `"timeout"` error after 20 seconds. Fly mode still works. |
| [Web services](/docs/web-services) | The matching service | `SphereServiceError` with code `"key"`. |
| [Static maps](/docs/web-services/maps-and-tiles#static-map-images) | Static map | The image doesn't load. |

## Using the key

Pass the key to `SphereProvider`:

```tsx
import { SphereProvider } from "gistda-sphere-react";

<SphereProvider apiKey="YOUR_API_KEY">
  <App />
</SphereProvider>
```

Keep it in an environment variable, so it stays out of source control.

```bash title="Next.js: .env.local"
NEXT_PUBLIC_SPHERE_API_KEY=your_api_key
```

```tsx
import { SphereProvider } from "gistda-sphere-react";

<SphereProvider apiKey={process.env.NEXT_PUBLIC_SPHERE_API_KEY!}>
```

```bash title="Vite: .env"
VITE_SPHERE_API_KEY=your_api_key
```

```tsx
import { SphereProvider } from "gistda-sphere-react";

<SphereProvider apiKey={import.meta.env.VITE_SPHERE_API_KEY}>
```

<Callout type="warn">
  Environment variables prefixed for the browser (`NEXT_PUBLIC_`, `VITE_`) still end up in your JavaScript. Host restrictions are what keep the key safe. For server-side calls with [`createSphereServices`](/docs/web-services#on-a-server), use a separate key without the browser prefix. Servers don't send the host that Sphere checks, so a host-restricted key also needs the `referer` option there.
</Callout>
